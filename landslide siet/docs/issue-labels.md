# Issue Label Guide

Use repository labels consistently; create any missing labels in GitHub before triage.

| Label | Purpose |
|---|---|
| `bug` | Reproducible incorrect behavior |
| `enhancement` | Product or engineering improvement |
| `data` | Data acquisition, licensing, quality, or provenance |
| `ml` | Feature engineering, training, validation, inference |
| `gis` | Spatial processing, maps, CRS, raster/vector workflows |
| `backend` | API, persistence, provider, or service work |
| `frontend` | User interface, accessibility, or PWA work |
| `rescue` | SOS, shelters, routes, responder flows |
| `security` | Authentication, privacy, secrets, abuse prevention |
| `documentation` | User, API, research, or operations documentation |
| `needs-review` | Unverified source, license, or design decision |
| `good first issue` | Bounded task suitable for a new contributor |

Do not label a source `open` or `verified` until its access method, licence, geographic coverage, and operational limits have been checked.
